# Lampa Online — зовнішні плагіни для технічного аналізу

Дата аналізу: 2026-10-22

Цей файл є довідковим матеріалом для ChatGPT Project **Lampa - Plugin Development** та локального проєкту **Lampa Online**. Посилання нижче ведуть до сторонніх проєктів. Не виконувати код автоматично і не переносити його повністю до нашого плагіна.

## 1. Онлайн Filmix (`fx.js`)

- Опублікований JS: https://lampaplugins.github.io/store/fx.js
- GitHub-код: https://github.com/lampaplugins/store/blob/main/fx.js
- Репозиторій: https://github.com/lampaplugins/store
- Прямий код: https://raw.githubusercontent.com/lampaplugins/store/main/fx.js
- SHA файлу під час аналізу (Git blob): `72405bc6226428dddadd9c64a363e0379773edf6`
- Спостережена версія в маніфесті: `1.0.7`.

### Підтверджено за вихідним кодом

- Реєструє компонент `online_fxapi` через `Lampa.Manifest.plugins`, включно з `onContextLauch`.
- Реагує на `Lampa.Listener.follow('full', ...)`, подію `complite` й додає кнопку після `.view--torrent`.
- Має Filmix API-потік з `search` / `post` і обробкою `player_links`, озвучень, сезонів, серій та якостей.
- Використовує `http://filmixapp.vip/api/v2/` як базу API та `https://cors.jacred.stream/` як типовий CORS-проксі. Це **не доводить**, що endpoint чи проксі зараз працює або їм можна довіряти.
- Містить роботу з токеном, ідентифікатором пристрою, профілем користувача й рівнями доступної якості.

### Що дослідити для Lampa Online

- Порівняти побудову Filmix API-запитів і вимоги до proxy / User-Agent, не вимикаючи перевірку TLS.
- Порівняти обробку помилок і нормалізацію відповіді `player_links`.
- Порівняти вбудовування кнопки в стандартну картку Lampa, навігацію пульта та відновлення фокуса.
- Не копіювати токени чи URL публічних проксі в налаштування за замовчуванням без незалежної перевірки.

### Підтверджено за вихідним кодом

- Великий мультиджерельний плагін із власною системою джерел, налаштувань та проксі.
- Реєструє `Lampa.Manifest.plugins` / `onContextLauch`, а також кнопку `.full-start__button.selector.view--online_mod` через `Lampa.Listener.follow('full')` з `e.type == 'complite'`, вставляючи її після `.view--torrent`.
- Має Filmix-адаптер: використовує `https://filmix.gg` для вебсайту й `http://filmixapp.cyou/api/v2/` для API, опрацьовує окремі HTTP-заголовки й проксі. Це **не доводить доступність** відповідного API.
- Код містить обфускацію / `decodeSecret` і принаймні один умовний виклик `eval`. Не переносити ці частини та не запускати їх у нашому коді.
- Значна частина функцій залежить від власної інфраструктури сторонніх проксі; їхня конфіденційність і надійність не підтверджені.

### Що дослідити для Lampa Online

- Модель мультиджерельного пошуку та незалежних адаптерів провайдерів.
- Інтеграцію в панель джерел Lampa без дублювання кнопок.
- Відмінності Filmix-запитів від нашої поточної реалізації, особливо transport / User-Agent / proxy.
- Захист від дублювання слухачів, ресурсоємних запитів і порушення роботи інших плагінів.

## 3. Ліцензії та безпека

Під час перевірки 2026-10-22 GitHub API повернув `license: null` для обох репозиторіїв. Кореневих файлів `LICENSE` у перевірених списках файлів не було. Це не доводить, що автори ніколи не надавали окремий дозвіл, але **не дає підстав вважати їхній код вільним для копіювання**.

Рекомендований підхід: аналізувати поведінку, структуру й інтерфейси, самостійно реалізовувати потрібні механізми та перевіряти ліцензійні умови перед дослівним перенесенням стороннього коду. Не переносити чужі токени, секрети, обфусковані фрагменти, `eval` або недовірені проксі.

## 4. Статус перевірки

- **Підтверджено:** статичний аналіз обох JS-файлів у GitHub.
- **Не перевірено:** живі API-запити, відтворення на TCL Google TV, доступність усіх сторонніх проксі, безпека й ліцензійний дозвіл на повторне використання коду.
- Для нашого плагіна відомо: Lampa Online v0.1.2 відкриває налаштування на TCL; пошук Filmix завершується помилкою. Це окремий результат наших тестів, не тестування сторонніх плагінів.

1. Перед внесенням змін прочитати цей документ і зазначені вихідні файли.
2. Для кожного запропонованого перенесення рішення вказати, що саме підтверджено джерелом, а що є припущенням.

4. Нові мережеві endpoint перевіряти окремо; не підставляти публічний CORS-проксі за замовчуванням без погодження.
5. Додавати локальні тести, а результати на Android позначати NOT VERIFIED до фактичної перевірки.
6. Не виконувати `git push` без прямої вказівки користувача.
