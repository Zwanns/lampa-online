# ZebMod 0.1.5 experimental

Попередня публічна назва — **Lampa Online**. Перейменування на **ZebMod** виконано у 0.1.3; поточний локальний випуск — **0.1.5 experimental**. Файл залишається `lampa-online.js`, URL встановлення — `https://zwanns.github.io/zeb.js`; наявні компоненти `lampa_online_*`, ключі Storage, CSS-класи, bootstrap-прапорець і технічний префікс логів `LampaOnline` не перейменовано. Наявні API URL/token/proxy/device ID та інші параметри зберігаються.

Автономний ES5 JavaScript-плагін із Filmix та окремим експериментальним адаптером Rezka. Повна картка → стандартна «Дивитись» → панель «Джерело» → **ZebMod** відкриває вибір **Rezka**, потім **Filmix**. Єдина кнопка джерела та альтернативний запуск через контекстне меню збережені. Існуючий FilmixScreen не переписувався.

**Rezka ще не підтверджена як працездатний провайдер.** Перевірка 2026-10-22: DNS і TLS `rezka.ag` PASS, головна HTTP 200 повернула anti-bot HTML замість каталогу. Challenge не обходився; живі search/detail/episodes/stream і TCL playback — **NOT VERIFIED**. Локальні fixtures перевіряють лише обмежений парсер відкритих HTTPS MP4/HLS URL; encoded-посилання не підтримуються. Повний звіт, маршрути, transport/privacy, обмеження й ручна TCL-перевірка: [Rezka_Integration.md](docs/Rezka_Integration.md). **Публікувати 0.1.5 як перевірену інтеграцію Rezka зарано.**

**Відоме обмеження: пошук Filmix API на TCL завершується помилкою.** За наданим у ТЗ звітом 0.1.3 на TCL вже PASS для встановленого ZebMod, налаштувань, стандартного джерела, відкриття компонента й Back. Версія **0.1.4** додає безпечну діагностику без консолі та порівняльний звіт; API URL, AJAX transport, proxy, авторизація, якості та Player залишаються без змін. Нова діагностика 0.1.4, реальний пошук і відтворення на TCL — **NOT VERIFIED**. Повторні живі HTTPS-проби з Windows та межі їхніх висновків наведені у [Filmix_API_Diagnostics.md](docs/Filmix_API_Diagnostics.md).

Провайдери цього випуску — **Filmix API v2** та **Rezka experimental**. Rezka працює окремо в гостьовому режимі через WebView AJAX без Filmix token/proxy, додаткових налаштувань, логіна чи імпорту cookies. Автоматичних дзеркал, HTTP fallback і стороннього CORS-проксі немає. Збірка, npm і додаткові бібліотеки для встановлення не потрібні; використовується jQuery, який уже надає Lampa.

**Встановлення через URL**

1. Розмісти `lampa-online.js` на своєму статичному HTTPS-хостингу з чинним сертифікатом. URL повинен віддавати сам JavaScript, а не HTML-сторінку перегляду файла.
2. У Lampa відкрий «Налаштування → Розширення / Плагіни → Додати плагін» і введи прямий HTTPS URL цього файла.
3. Повністю перезапусти Lampa після встановлення або оновлення: одночасне завантаження двох різних версій не підтримується.
4. Для Filmix відкрий «Налаштування → ZebMod» та вкажи доступну базову адресу Filmix API v2. Ці параметри не застосовуються до Rezka; її домен фіксований — `https://rezka.ag`.
5. Відкрий повну картку фільму або серіалу → стандартну кнопку «Дивитись» → панель «Джерело» → «ZebMod». Альтернатива: контекстне меню картки → «Плагіни / Розширення» → «ZebMod». Назви стандартних пунктів залежать від мови й версії Lampa.

Надана адреса встановлення: `https://zwanns.github.io/zeb.js`. Вона використовувалася в першому тесті за звітом користувача; її поточний вміст у цій роботі не перевірявся й не оновлювався. Версія 0.1.5 підготовлена **лише локально** в `lampa-online.js`; для контрольного тесту користувач має сам оновити опублікований файл. Git commit і push не виконувалися.

**Сценарій 0.1.5 та перевірки**

Після ZebMod обери провайдера. Rezka: ручний вибір результату → озвучення → для серіалу сезон/серія → реально отримана якість → Player. Back повертає попередній екран з фокусом, скасовуючи запит. Вибір оригінальної назви для повторного пошуку теж ручний. Playlist містить тільки поточний отриманий потік; наступні серії не вигадуються. За challenge/403/авторизації сценарій завершується діагностикою без обходу. HTTP 0 не дозволяє визначити CORS/DNS/TLS. Filmix відкриває свій попередній екран із діагностикою 0.1.4.

**LOCAL PASS:** 212 тестів (154 попередні + 58 нових), syntax, ES5, diff check. **NETWORK VERIFIED:** лише DNS/TLS і challenge головної Rezka. **TCL VERIFIED: NOT VERIFIED.** Покрокова перевірка D-pad/touch/Back, Filmix regression та search/detail/stream — у [розділі TCL](docs/Rezka_Integration.md#ручна-перевірка-на-tcl). Нижче збережено попередні інструкції та історію Filmix; після вибору ZebMod у 0.1.5 спочатку обирай **Filmix** для цих сценаріїв.

**Діагностика Filmix без консолі (0.1.4)**

За помилки search/post на поточному екрані з'являється читабельний блок: `stage`, `Transport: WebView AJAX`, `HTTP`, `Error`, час у ms, ознаки JSON/Filmix і коротке пояснення. Рядок повтору доступний через OK; Up/Down і Back використовують наявну навігацію. Помилка `user_profile` залишається видимою при продовженні гостьового пошуку. Після завершення запиту доступний окремий рядок «Повторити user_profile і пошук»; він повторює наявну послідовність, не змінюючи token або device ID.

Приклад **синтетичного формату, не результат TCL**: `Етап: search; Transport: WebView AJAX; HTTP: 0; Error: error; Час: 1200 ms; JSON: unknown; Filmix: unknown`. Повідомлення пояснює: причина невідома, можливі мережа, DNS, CORS або TLS. **Status 0 не встановлює конкретну причину.** Для HTTP 401/403, 404, 429, 5xx, timeout, parsererror та abort є окрема класифікація. Валідний JSON з неочікуваною структурою відрізняється від некоректного JSON.

Діагностичні блоки й власні логи не містять token, device ID, URL/query/proxy, cookies, headers, повних відповідей або exception-об'єктів. Додатковий scalar-лог має вигляд `LampaOnline | diagnostic | stage=search transport=ajax http=0 error=error elapsed_ms=1200 json=unknown filmix=unknown`. Старий формат network-log збережено. Для error-відповідей JSON/Filmix лишаються unknown, оскільки тіло помилки навмисно не читається. Тривалість вимірюється monotonic clock, якщо доступний, і обмежується 0–86400000 ms.

Парсер movie Array збережено. Якщо post містить непорожній movie Object і не дає підтримуваних джерел, діагностика пояснює обмеження клієнта. Це не доказ мережевої помилки; формати покриті [синтетичними fixtures](tests/fixtures/filmix/README.md). Нових якостей або URL не створюється.

22.10.2026 у Windows/Node обидва `filmixapp.cyou` і `filmixapp.vip` дали `ERR_TLS_CERT_ALTNAME_INVALID`. Перевірений як гіпотеза `api.filmix.tv` має валідний TLS, але GET search повернув **405**, а не Filmix search Array; його не встановлено як новий API. Живі search/playback на TCL лишаються NOT VERIFIED. Детальні таблиці трьох реалізацій, headers/auth/proxy, гіпотези, результати проб і наступне виправлення — у [технічному звіті](docs/Filmix_API_Diagnostics.md).

**Інтеграція у стандартну панель «Джерело» (0.1.3)**

Один `Lampa.Listener.follow('full', ...)` обробляє саме `e.type === 'complite'`. Плагін шукає `.buttons--container` лише в `e.object.activity.render()` поточної картки; якщо цей API відсутній, використовує локальний `e.body`. Кнопка `.full-start__button.selector.view--lampa-online` із SVG відтворення та назвою ZebMod додається прямим дочірнім елементом після останньої `.view--torrent` цього контейнера. Якщо торрентів немає — у кінець того самого контейнера. Якщо контейнера немає, вставка пропускається: глобального пошуку чи власної панелі немає.

Механізм звірено 22 жовтня 2026 року з Lampa, commit `71733ed81f4b13ac1ed1b3328cbbaa7e01afdbd2`: [full/start/buttons.js](https://github.com/yumata/lampa-source/blob/71733ed81f4b13ac1ed1b3328cbbaa7e01afdbd2/src/components/full/start/buttons.js) збирає прямі `.full-start__button` контейнера при відкритті стандартної панелі; [full.js](https://github.com/yumata/lampa-source/blob/71733ed81f4b13ac1ed1b3328cbbaa7e01afdbd2/src/components/full.js) викликає `groupButtons` після `full/complite`. Використано лише спосіб вставки джерела, зіставлений із [online.js](https://github.com/yumata/lampa-source/blob/71733ed81f4b13ac1ed1b3328cbbaa7e01afdbd2/plugins/online/online.js) та [Shots view.js](https://github.com/yumata/lampa-source/blob/71733ed81f4b13ac1ed1b3328cbbaa7e01afdbd2/plugins/shots/utils/view.js); їхній код не копіюється цілком.

`hover:enter` та старий `onContextLauch` викликають одну внутрішню `openOnline(card)` з `Lampa.Activity.push()` і компонентом вибору `lampa_online_provider_screen`. Він відкриває окремий `lampa_online_rezka_screen` або наявний `lampa_online_filmix_screen`. Об'єкт `movie` передається повністю, включно з оригінальною назвою, датою/роком, ознаками та сезонами серіалу; `search` обирається наявною `titleOf()`. Повторний `complite` використовує наявну кнопку й замінює лише власний обробник `.lampaOnlineSource`, оновлюючи дані картки. Сталий bootstrap-прапорець захищає від повторної реєстрації Listener при завантаженні того самого JS.

Стандартна «Дивитись», її обробники, групування, інші джерела й Controller не перевизначаються. Up/Down/OK у панелі та повернення її фокуса забезпечує Lampa. Back з екрана пошуку використовує наявний `Activity.backward()`; глобального перехоплення Back немає. Якщо у збірці немає `full/complite`, локального контейнера або сумісного групування джерел, новий спосіб запуску може бути недоступний; залишається контекстне меню. Якщо налаштовано пріоритетне джерело, Lampa може показувати його окремою кнопкою — це стандартна поведінка хоста.

**Назва встановленого розширення**

Маніфест, налаштування, назва Activity та кнопка джерела використовують **ZebMod**; контекстне меню має локалізовані назви uk/ru/en з ZebMod. Заголовки/підзаголовки Filmix-екранів містять **ZebMod · Filmix** зі збереженням назви фільму, сезону чи озвучення.

Перевірено Lampa commit `71733ed81f4b13ac1ed1b3328cbbaa7e01afdbd2`: [extensions/item.js](https://github.com/yumata/lampa-source/blob/71733ed81f4b13ac1ed1b3328cbbaa7e01afdbd2/src/interaction/extensions/item.js) показує `data.name`, [extensions/main.js](https://github.com/yumata/lampa-source/blob/71733ed81f4b13ac1ed1b3328cbbaa7e01afdbd2/src/interaction/extensions/main.js) бере локальні записи з `Plugins.get()`, а [core/plugins.js](https://github.com/yumata/lampa-source/blob/71733ed81f4b13ac1ed1b3328cbbaa7e01afdbd2/src/core/plugins.js) повертає поверхневу копію масиву з посиланнями на записи. Одного `Manifest.plugins.name` недостатньо для перейменування встановленої картки.

Під час ініціалізації плагін шукає рівно один запис із точним `url === 'https://zwanns.github.io/zeb.js'` у локальному списку `Lampa.Plugins.get()` і в актуальному збереженому масиві стандартного ключа `plugins`. Змінюється тільки поле `name` нашого запису на `ZebMod`, зі збереженням URL, статусу, метаданих, порядку та полів усіх інших записів. Після збереження оновлюється посилання на локальний запис у пам'яті; при повторному запуску з уже збереженою назвою зайвого запису немає. `Plugins.save()` не викликається, оскільки він логує весь список URL; глобальні методи не перевизначаються, нових мережевих викликів немає.

Якщо API відсутній, список некоректний, запис відсутній хоча б в одному списку, URL відрізняється або є дублікати точного URL, перейменування встановленої картки пропускається. За помилки запису Storage плагін продовжує запуск. Інші URL хостингу, варіанти з query/hash і записи з CUB-акаунта автоматично не змінюються. Для такого встановлення використай штатне меню свого розширення → «Змінити назву» → `ZebMod`, якщо воно доступне у збірці. Після оновлення JS повністю перезапусти Lampa й повторно відкрий список розширень; уже намальована картка може потребувати повторного відкриття. Фактичне відображення й збереження на TCL/у браузері — **NOT VERIFIED**; локально перевірено контракт даних через mocks.

**Налаштування**

| Ключ Lampa.Storage | Типове значення | Призначення |
| --- | --- | --- |
| `lampa_online_api_url` | `https://filmixapp.cyou/api/v2/` | Базова адреса API, без query/hash, з `/api/v2/`. Це початкове, **не підтверджене як працездатне** значення. |
| `lampa_online_token` | порожньо | Власний Filmix device token. Пароль не потрібен. |
| `lampa_online_proxy` | порожньо | Необов'язковий власний довірений HTTPS CORS-проксі. Публічного проксі за замовчуванням немає. |
| `lampa_online_device_id` | автоматично збережені 16 hex-символів | Сталий ID пристрою. Наявне значення з 0.1.0 зберігається. Для раніше прив'язаного токена використовуй відповідний device ID. |

Параметри зберігаються стандартним Lampa.Storage; фактичне збереження на Android треба перевірити після перезапуску. Не змінюй device ID без потреби.

Проксі підтримує початковий формат **префікс + повний URL**: налаштування `https://proxy.example/` дає запит виду `https://proxy.example/https://api.example/api/v2/search?...`. Це приклади адрес, не готові сервіси. Проксі формату `?url=` чи з кодуванням усього upstream URL не підтримується. Проксі отримує токен; для upstream також слід використовувати HTTPS. Прямий HTTP API відхиляється зі зрозумілим повідомленням. Автоматичного переходу з HTTPS на HTTP немає.

**Знайдені проблеми та виправлення**

У версії **0.1.2**:

- Для `lampa_online_api_url`, `lampa_online_token`, `lampa_online_proxy`, `lampa_online_device_id` додано `values: ''`. `SettingsApi.addParam()` реєструє input через `Params.select()`, а `Params.update()` без цього значення звертався до `undefined[key]` і спричиняв TypeError. Підтверджено за [SettingsApi](https://github.com/yumata/lampa-source/blob/71733ed81f4b13ac1ed1b3328cbbaa7e01afdbd2/src/interaction/settings/api.js) та [Params](https://github.com/yumata/lampa-source/blob/71733ed81f4b13ac1ed1b3328cbbaa7e01afdbd2/src/interaction/settings/params.js). Ключі Storage й наявні значення збережено.
- Додано парні логи початку/завершення `search`, `user_profile` і `post`, HTTP-статус, безпечний тип помилки, результат JSON parsing і перевірку очікуваної структури. При закритті компонента запит завершується як `abort`; пізні callbacks ігноруються.
- При некоректному JSON зберігається реальний HTTP-статус. Коректний JSON із неочікуваною структурою відрізняється від помилки синтаксису JSON. Некоректний профіль дає повідомлення та гостьовий ліміт; пошук продовжується.
- `$.ajax`, таймаути, обмежений пошук за оригінальною назвою та ручний повтор залишено. Нових автоматичних повторів немає.

Збережені виправлення **0.1.1**:

- Захист від повторного запуску був прив'язаний до версії, а завантаження до появи Lampa просто пропускалося. Тепер один сталий прапорець захищає bootstrap, очікування Lampa та реєстрації; app/ready handler видаляється після запуску.
- `Reguest.clear()` у перевіреному Lampa лише очищає callbacks, а обробник помилок логує повний URL разом із query. Мережевий транспорт локально замінено на jQuery AJAX із `global: false`, скасуванням XHR, захистом від пізніх відповідей та власним watchdog. Це цільова заміна мережевого шару, решта компонентної архітектури збережена. Пошук/post: 15 с; профіль: 8 с.
- Раніше профіль завантажувався паралельно й міг змінити обмеження якості після побудови списків. Тепер він завершується перед пошуком; рядковий прапорець `"0"` не дає PRO-доступ. За непідтвердженого профілю діє гостьовий ліміт.
- Гостьовий ліміт для шаблонів якості встановлено консервативно у 480p; підтверджений звичайний профіль — 720p, PRO — 1080p, PRO+ — 2160p. Це клієнтська політика, а не підтвердження доступу: остаточні права визначає сервер. Для прямого потоку без оголошеної роздільності, зокрема HLS master, використовується наданий URL без вигадування варіантів якості.
- Back із джерел повторно запускав пошук, міг залишати активний post-запит і втрачав вибраний результат. Тепер Back скасовує запит і відновлює кешований список та позицію фокуса. Повернення між сезонами й серіями також зберігає фокус.
- Фокус міг оновлюватися під час відкритого меню/плеєра. Тепер колекція оновлюється лише коли екран володіє активним content controller. Рядок «Назад» доступний навіть під час завантаження або порожнього результату.
- Додано перевірку JSON/структури пошуку, відкидання некоректних результатів, title/name/original_title/original_name, показ року та оригінальної назви. Порожня відповідь один раз повторює пошук за оригінальною назвою; користувач завжди сам обирає результат.
- Залишено тільки оголошені якості; `%s` без списку qualities не розгортається. MP4 і HLS передаються у стандартний Player; HTML/embed, некоректні URL та відомі якості понад ліміт відхиляються. Для серіалів підтримуються numeric episode objects, масиви та названі записи з `sNeN` у URL; номери сортуються чисельно. Сезон `-1` показується як 1.
- Прибрано циклічне посилання `first.playlist`: об'єкт запуску серіалу копіюється окремо від його playlist. Список є в даних запуску для Android bridge і передається через `Lampa.Player.playlist()` для вбудованого плеєра. Додано повідомлення при синхронному збої запуску й стандартний `error` callback для фатальної помилки потоку.
- `Storage.get()` може перетворювати цифрові token/device ID на числа, гублячи початкові нулі або точність. У цьому випадку текст читається через перевірений `Storage.value()`.
- `destroy()` тепер скасовує обидва запити й таймери, прибирає власні обробники рядків, очищує дані та замикання свого controller. Повторне знищення безпечне; чужий controller не змінюється. CSS-класи отримали префікс `lampa-online-`.

Мережеві логи мають формат `LampaOnline | network | stage | result`, наприклад:

```text
LampaOnline | network | search | start http=0 error=none json=unknown filmix=unknown
LampaOnline | network | search | complete http=200 error=none json=true filmix=true
LampaOnline | network | user_profile | complete http=0 error=error json=unknown filmix=unknown
LampaOnline | network | search | complete http=200 error=parsererror json=false filmix=false
```

Це приклади формату, не результати живого Filmix. `stage` — лише `search`, `user_profile` або `post`; `error` — `none`, `timeout`, `error`, `parsererror`, `abort`. `http=0` означає, що HTTP-статус недоступний (на початку запиту він ще невідомий); це не HTTP-код сервера. `json=true` означає успішний parsing, `filmix=true` — схожість на очікувану структуру, без гарантії працездатності потоків чи прав доступу. Порожній масив пошуку також коректний. `unknown` означає відсутність даних для перевірки. Завершення реєструється один раз, у тому числі після watchdog timeout або скасування.

Інші логи містять лише локальний етап, кількість або ліміт якості. Текст сервера, URL, query пошуку, токен, device ID і приватні дані профілю не виводяться. Сам стандартний Player Lampa може логувати переданий URL потоку; його глобальне логування плагін не змінює.

Актуальні переглянуті приклади зберігають цей API host: [Filmix у Lampa](https://github.com/yumata/lampa-source/blob/71733ed81f4b13ac1ed1b3328cbbaa7e01afdbd2/plugins/online/filmix.js) використовує `http://filmixapp.cyou/api/v2/`, `search?story=…`, `post/{id}`, `user_profile` і `user_dev_*`; [go-filmix Discover](https://github.com/n0madic/go-filmix/blob/32e4e4f522537943a035ddf1be303782e0b7f6d0/client/discover.go) містить HTTP/HTTPS варіанти того самого host. [Побудова URL go-filmix](https://github.com/n0madic/go-filmix/blob/32e4e4f522537943a035ddf1be303782e0b7f6d0/internal/httpx/url.go) додає `user_dev_id`, `user_dev_name`, `user_dev_vendor`, `user_dev_os`, `user_dev_apk`, а за наявності — `user_dev_token`. У плагіні ці поля присутні; додатково є `app_lang=ru_RU`, APK `2.2.13`, ім'я/vendor `Lampa`, OS `Android`. Точну чинну вимогу сервера до їхніх значень без живої відповіді встановити неможливо. Це сторонні клієнти, а не офіційна специфікація чи доказ доступності API.

За [документацією XMLHttpRequest](https://developer.mozilla.org/en-US/docs/Web/API/XMLHttpRequest/status), мережеві помилки можуть давати status 0. JS не отримує достатньо деталей, щоб розрізнити DNS, TLS, CORS і розрив мережі; для [CORS-помилок](https://developer.mozilla.org/en-US/docs/Web/HTTP/Guides/CORS) потрібні деталі консолі браузера. Тому лог `http=0 error=error` не встановлює причину. Виявлений TLS-збій — доказ для цього середовища, а не остаточний діагноз TCL.

У браузері та Android WebView поточний `$.ajax` використовує XHR і підпорядковується CORS. На Android результат додатково залежить від версії WebView, DNS/мережі пристрою, довірених сертифікатів і [network security configuration застосунку](https://developer.android.com/privacy-and-security/security-config). Дозвіл змішаного HTTP/HTTPS визначає [WebSettings](https://developer.android.com/reference/android/webkit/WebSettings#MIXED_CONTENT_NEVER_ALLOW). HTTP-адреса в чужому клієнті не доводить її придатність для цього HTTPS-плагіна. Нативний Android HTTP bridge має іншу мережеву поведінку, але тут він не використовується; транспорт не замінено.

Працездатність поточного HTTPS API **не підтверджено**. Адреса залишається змінюваною. Ім'я з сертифіката не використовується як новий API; `filmix.gg` є сайтом і не замінює API. TLS не вимикали, автоматичний HTTP fallback, випадкові дзеркала й публічні проксі не додавали. Для наступного живого тесту потрібна підтверджена адреса Filmix API v2 з чинним сертифікатом і CORS або власний довірений HTTPS-проксі.

2. Відкрий повну картку фільму з каталогу → стандартну «Дивитись». У панелі «Джерело» очікується рівно один **ZebMod** із SVG відтворення; торренти, Shots, трейлери та встановлені онлайн-джерела мають залишитися доступними, якщо ця збірка їх надає.

4. Натисни Back під час пошуку або після помилки. Очікується повернення до тієї ж повної картки з відновленням штатного фокуса на «Дивитись»/відповідному елементі Lampa. Знову відкрий панель, перевір один ZebMod й запусти інше встановлене джерело. Також перевір Back із самої панелі джерел.
5. Повтори для серіалу з назвою та оригінальною назвою. Екран має отримати саме вибраний серіал. Рік і дані сезонів передаються у `movie`; показ результатів/серій залежить від доступності Filmix API й у цьому завданні не підтверджується.
6. Кілька разів відкрий/закрий панель, повернися з плагіна, відкрий той самий фільм повторно та перейди між різними фільмами/серіалами. Щоразу має бути один пункт і одна реакція на OK, з даними поточної картки. Якщо можливо повторно завантажити саме 0.1.4 у тій самій сесії, перевір також цей сценарій.
7. Перевір альтернативний запуск: контекстне меню картки → «Плагіни / Розширення» → «ZebMod». Він має відкривати той самий компонент. Налаштування ZebMod мають залишитися в одному екземплярі зі старими значеннями.
8. Зафіксуй окремі PASS/FAIL для появи джерела, запуску, фільму/серіалу, повторних відкриттів, фокуса/Back і доступності інших джерел. Не передавай токен, device ID чи приватні URL. До виконання цих кроків усі перевірки реального TCL залишаються **NOT VERIFIED**.
9. Відкрий список встановлених розширень. Для локального запису з точним URL `https://zwanns.github.io/zeb.js` очікується **ZebMod**. Перезапусти Lampa та перевір збереження назви, старих налаштувань і назв інших розширень. Перевір також назву в налаштуваннях, стандартному джерелі, контекстному меню та заголовку компонента. Для іншого URL або несумісної збірки врахуй обмеження розділу про назву встановленого розширення.
10. Без консолі дочекайся помилки Filmix. Запиши stage, transport, HTTP, error, elapsed і JSON/Filmix. Натисни повтор, перевір новий час і Back. За помилки профілю дочекайся гостьового search та перевір «Повторити user_profile і пошук», включно з Back під час запиту. Не надсилай token/device ID, URL запитів, cookies/headers або API body. Детальний порядок та інтерпретація результатів — у [звіті](docs/Filmix_API_Diagnostics.md#ручна-перевірка-на-tcl).

**Попередні сценарії діагностики Filmix (збережено з 0.1.2)**

Це окремі сценарії для майбутньої перевірки API/відтворення після відновлення доступу. Вони не виконувалися під час інтеграції 0.1.3 та не є умовою локального PASS нового джерела; згадки 0.1.2 нижче стосуються попереднього випуску.

1. Після ручного оновлення опублікованого JS до локальної 0.1.2 повністю перезапусти Lampa. Запиши версії Lampa, Android, Android System WebView та модель TCL; у логах має бути `LampaOnline v0.1.2.ready`. Наявність старої версії означає, що ще завантажується кеш або старий файл.
2. Відкрий «Налаштування → ZebMod». Очікуй чотири текстові поля без TypeError й збереження попередніх значень. Перевір редагування API URL, token, proxy і device ID: спочатку без реальних облікових даних, потім поверни власні потрібні значення. Вийди та відкрий налаштування знову, потім повністю перезапусти Lampa й перевір збереження всіх чотирьох полів. Не надсилай скриншоти токена/device ID; пункт налаштувань і контекстне меню мають бути в одному екземплярі.
3. Відкрий картку відомого доступного фільму → контекстне меню → «Плагіни / Розширення» → «ZebMod». Очікуй окремі результати з назвою, роком та ID. Нічого не повинно стартувати автоматично.
4. Обери правильний результат, потім озвучення. Перевір відкриття стандартного плеєра, доступні якості та повернення Back на той самий рядок.
5. Перевір серіал: сезон → озвучення → список серій. Переконайся, що 2 розташована перед 10, обрана серія правильна, наступна серія є в плейлисті. Після плеєра фокус має залишитись на обраній серії.
6. Перевір Up/Down/OK. Left має переходити за правилами Navigator або відкривати меню; Right передається Navigator. Back із серій веде до сезонів/озвучень, наступний — до результатів, ще один — до попереднього екрана Lampa. Для фільму: джерела → результати → попередній екран. Повтори мишею/сенсором, якщо вони доступні.
7. Запусти пошук і одразу вийди Back. Повтори з post-запитом. Пізня відповідь не повинна повернути закритий екран, змінити чужий фокус або залишити нескінченний loader. Знову відкрий компонент.
8. Вимкни мережу або тимчасово введи недоступну API-адресу. Очікуй повідомлення про помилку/таймаут і рядок повтору, без JavaScript crash і нескінченного loader. Перевір пару `start`/`complete` для `search`; із власним токеном — спочатку `user_profile`, потім `search`. За помилки профілю очікуй повідомлення та гостьовий ліміт. Для `http=0 error=error` запиши окрему причину з консолі WebView (TLS/DNS/CORS), якщо вона доступна: сам status 0 її не визначає. На поточному default API можливий TLS-збій, виявлений локально; це не PASS пошуку. Поверни мережу/підтверджену адресу API й повтори запит. Для відтворюваних 401/403/404/429/500, timeout і некоректного JSON використовуй лише власний тестовий API/проксі; звір `http`, `error`, `json`, `filmix` у логах. Пошук без результатів має завершувати loader. Для успішного пошуку очікуй `json=true filmix=true`; це ще не PASS відтворення.
9. За потреби введи свій легітимний token і відповідний device ID. Повторно відкрий компонент: обмеження якості має відповідати підтвердженому профілю та оголошеним джерелом варіантам. Реєстрація акаунта або отримання токена плагіном не виконується.
10. Повністю закрий і запусти Lampa. Перевір збереження параметрів, повторне відкриття фільму/серіалу та відсутність дублікатів. Переконайся, що власні логи `LampaOnline` не містять токена, device ID, URL із query або приватних даних профілю. Після виходу Back під час запиту має бути одне завершення `error=abort`, без пізнього оновлення екрана. Зафіксуй окремо налаштування, пошук, навігацію та реальне відтворення як PASS/FAIL із кроками відтворення; до цього перевірки 0.1.2 на пристрої залишаються NOT VERIFIED.

**Залишкові обмеження**

- Поточний API host має проблему TLS у середовищі перевірки; успішний живий сценарій ще не підтверджено. Плагін не визначає нові host-и автоматично.
- AJAX працює за правилами CORS WebView/браузера. Нативний Android HTTP bridge не використовується через його логування credential-bearing URL у перевіреному Lampa.Reguest.
- Підтримуються тільки надані джерелом прямі MP4/HLS URL та початкові шаблони якості. DASH, декодування прихованих посилань, DRM, обхід авторизації й обмежень не реалізовані.
- Реальну доступність потоку, кодеки, серверні права, геообмеження й поведінку зовнішнього Android-плеєра потрібно перевіряти вручну. Стандартний error callback покриває фатальні помилки вбудованого плеєра; зовнішній застосунок може не повідомити Lampa про помилку.
- Контракти старих/модифікованих збірок Lampa можуть відрізнятися. Критерії NOT VERIFIED не означають PASS.
