# Lampa Online 0.1.2

Автономний ES5 JavaScript-плагін для пошуку фільмів і серіалів у Filmix та передавання доступних MP4/HLS-потоків у стандартний Lampa.Player. Версія **0.1.2** виправляє відкриття налаштувань і додає безпечну мережеву діагностику. За наданим звітом першого тесту на TCL Google TV версія 0.1.1 завантажувалася з GitHub Pages (HTTP 200), реєструвала налаштування й контекстне меню та відкривала компонент пошуку. Відкриття налаштувань і з'єднання з API завершувалися помилками. Повторний тест 0.1.2 на TCL і реальне відтворення: **NOT VERIFIED**.

Підтримуване джерело цього випуску — лише **Filmix API v2**. Інші джерела з ToDo.md не реалізовані. Збірка, npm і додаткові бібліотеки для встановлення не потрібні; використовується jQuery, який уже надає Lampa.

**Встановлення через URL**

1. Розмісти `lampa-online.js` на своєму статичному HTTPS-хостингу з чинним сертифікатом. URL повинен віддавати сам JavaScript, а не HTML-сторінку перегляду файла.
2. У Lampa відкрий «Налаштування → Розширення / Плагіни → Додати плагін» і введи прямий HTTPS URL цього файла.
3. Повністю перезапусти Lampa. Після оновлення з 0.1.0 також потрібен перезапуск: одночасне завантаження двох різних версій не підтримується.
4. Відкрий «Налаштування → Lampa Online» та вкажи доступну базову адресу Filmix API v2.
5. Відкрий контекстне меню картки → «Плагіни / Розширення» → «Lampa Online». Назви пунктів залежать від мови й версії Lampa.

Надана адреса встановлення: `https://zwanns.github.io/zeb.js`. Вона використовувалася в першому тесті за звітом користувача; її поточний вміст у цій роботі не перевірявся й не оновлювався. Версія 0.1.2 підготовлена **лише локально** в `lampa-online.js`; для повторного тесту користувач має сам оновити опублікований файл. Git commit і push не виконувалися.

**Налаштування**

| Ключ Lampa.Storage | Типове значення | Призначення |
| --- | --- | --- |
| `lampa_online_api_url` | `https://filmixapp.cyou/api/v2/` | Базова адреса API, без query/hash, з `/api/v2/`. Це початкове, **не підтверджене як працездатне** значення. |
| `lampa_online_token` | порожньо | Власний Filmix device token. Пароль не потрібен. |
| `lampa_online_proxy` | порожньо | Необов'язковий власний довірений HTTPS CORS-проксі. Публічного проксі за замовчуванням немає. |
| `lampa_online_device_id` | автоматично збережені 16 hex-символів | Сталий ID пристрою. Наявне значення з 0.1.0 зберігається. Для раніше прив'язаного токена використовуй відповідний device ID. |

Параметри зберігаються стандартним Lampa.Storage; фактичне збереження на Android треба перевірити після перезапуску. Не змінюй device ID без потреби.

Проксі підтримує початковий формат **префікс + повний URL**: налаштування `https://proxy.example/` дає запит виду `https://proxy.example/https://api.example/api/v2/search?...`. Це приклади адрес, не готові сервіси. Проксі формату `?url=` чи з кодуванням усього upstream URL не підтримується. Проксі отримує токен; для upstream також слід використовувати HTTPS. Прямий HTTP API відхиляється зі зрозумілим повідомленням. Автоматичного переходу з HTTPS на HTTP немає.

**Знайдені проблеми та виправлення**

У версії **0.1.2**:

- Для `lampa_online_api_url`, `lampa_online_token`, `lampa_online_proxy`, `lampa_online_device_id` додано `values: ''`. `SettingsApi.addParam()` реєструє input через `Params.select()`, а `Params.update()` без цього значення звертався до `undefined[key]` і спричиняв TypeError. Підтверджено за [SettingsApi](https://github.com/yumata/lampa-source/blob/71733ed81f4b13ac1ed1b3328cbbaa7e01afdbd2/src/interaction/settings/api.js) та [Params](https://github.com/yumata/lampa-source/blob/71733ed81f4b13ac1ed1b3328cbbaa7e01afdbd2/src/interaction/settings/params.js). Ключі Storage й наявні значення збережено.
- Додано парні логи початку/завершення `search`, `user_profile` і `post`, HTTP-статус, безпечний тип помилки, результат JSON parsing і перевірку очікуваної структури. При закритті компонента запит завершується як `abort`; пізні callbacks ігноруються.
- При некоректному JSON зберігається реальний HTTP-статус. Коректний JSON із неочікуваною структурою відрізняється від помилки синтаксису JSON. Некоректний профіль дає повідомлення та гостьовий ліміт; пошук продовжується.
- `$.ajax`, таймаути, обмежений пошук за оригінальною назвою та ручний повтор залишено. Нових автоматичних повторів немає.

Збережені виправлення **0.1.1**:

- Захист від повторного запуску був прив'язаний до версії, а завантаження до появи Lampa просто пропускалося. Тепер один сталий прапорець захищає bootstrap, очікування Lampa та реєстрації; app/ready handler видаляється після запуску.
- `Reguest.clear()` у перевіреному Lampa лише очищає callbacks, а обробник помилок логує повний URL разом із query. Мережевий транспорт локально замінено на jQuery AJAX із `global: false`, скасуванням XHR, захистом від пізніх відповідей та власним watchdog. Це цільова заміна мережевого шару, решта компонентної архітектури збережена. Пошук/post: 15 с; профіль: 8 с.
- Раніше профіль завантажувався паралельно й міг змінити обмеження якості після побудови списків. Тепер він завершується перед пошуком; рядковий прапорець `"0"` не дає PRO-доступ. За непідтвердженого профілю діє гостьовий ліміт.
- Гостьовий ліміт для шаблонів якості встановлено консервативно у 480p; підтверджений звичайний профіль — 720p, PRO — 1080p, PRO+ — 2160p. Це клієнтська політика, а не підтвердження доступу: остаточні права визначає сервер. Для прямого потоку без оголошеної роздільності, зокрема HLS master, використовується наданий URL без вигадування варіантів якості.
- Back із джерел повторно запускав пошук, міг залишати активний post-запит і втрачав вибраний результат. Тепер Back скасовує запит і відновлює кешований список та позицію фокуса. Повернення між сезонами й серіями також зберігає фокус.
- Фокус міг оновлюватися під час відкритого меню/плеєра. Тепер колекція оновлюється лише коли екран володіє активним content controller. Рядок «Назад» доступний навіть під час завантаження або порожнього результату.
- Додано перевірку JSON/структури пошуку, відкидання некоректних результатів, title/name/original_title/original_name, показ року та оригінальної назви. Порожня відповідь один раз повторює пошук за оригінальною назвою; користувач завжди сам обирає результат.
- Залишено тільки оголошені якості; `%s` без списку qualities не розгортається. MP4 і HLS передаються у стандартний Player; HTML/embed, некоректні URL та відомі якості понад ліміт відхиляються. Для серіалів підтримуються numeric episode objects, масиви та названі записи з `sNeN` у URL; номери сортуються чисельно. Сезон `-1` показується як 1.
- Прибрано циклічне посилання `first.playlist`: об'єкт запуску серіалу копіюється окремо від його playlist. Список є в даних запуску для Android bridge і передається через `Lampa.Player.playlist()` для вбудованого плеєра. Додано повідомлення при синхронному збої запуску й стандартний `error` callback для фатальної помилки потоку.
- `Storage.get()` може перетворювати цифрові token/device ID на числа, гублячи початкові нулі або точність. У цьому випадку текст читається через перевірений `Storage.value()`.
- `destroy()` тепер скасовує обидва запити й таймери, прибирає власні обробники рядків, очищує дані та замикання свого controller. Повторне знищення безпечне; чужий controller не змінюється. CSS-класи отримали префікс `lampa-online-`.

Мережеві логи мають формат `LampaOnline | network | stage | result`, наприклад:

```text
LampaOnline | network | search | start http=0 error=none json=unknown filmix=unknown
LampaOnline | network | search | complete http=200 error=none json=true filmix=true
LampaOnline | network | user_profile | complete http=0 error=error json=unknown filmix=unknown
LampaOnline | network | search | complete http=200 error=parsererror json=false filmix=false
```

Це приклади формату, не результати живого Filmix. `stage` — лише `search`, `user_profile` або `post`; `error` — `none`, `timeout`, `error`, `parsererror`, `abort`. `http=0` означає, що HTTP-статус недоступний (на початку запиту він ще невідомий); це не HTTP-код сервера. `json=true` означає успішний parsing, `filmix=true` — схожість на очікувану структуру, без гарантії працездатності потоків чи прав доступу. Порожній масив пошуку також коректний. `unknown` означає відсутність даних для перевірки. Завершення реєструється один раз, у тому числі після watchdog timeout або скасування.

Інші логи містять лише локальний етап, кількість або ліміт якості. Текст сервера, URL, query пошуку, токен, device ID і приватні дані профілю не виводяться. Сам стандартний Player Lampa може логувати переданий URL потоку; його глобальне логування плагін не змінює.

**Повторна діагностика 21 жовтня 2026 року**

Перевірено з цього Windows/Node.js середовища: один гостьовий HTTPS GET до `search` з параметрами поточного плагіна, порожнім токеном, синтетичним device ID та заголовком Origin. Реальні облікові дані не використовувалися. TLS-перевірка ввімкнена; редиректи Node HTTPS автоматично не виконує.

| --- | --- |
| Формування запиту | **LOCAL PASS**: GET `/api/v2/search`, `story` та token/device ID кодуються через `encodeURIComponent`; `user_profile` виконується перед пошуком, лише коли задано токен. |
| DNS через системний resolver (`dns.lookup`) | **PASS у цьому середовищі**: `filmixapp.cyou` → `185.80.234.68` (IPv4). Окремі прямі DNS-запити `resolve4/resolve6` повернули `ECONNREFUSED`; це обмеження цього шляху resolver, а не доказ відсутності домену. IPv6 не підтверджено. |

| JSON і структура Filmix | Живий API: **NOT VERIFIED**; mock search/profile, некоректний JSON і неочікувана структура: **LOCAL PASS**. |

Актуальні переглянуті приклади зберігають цей API host: [Filmix у Lampa](https://github.com/yumata/lampa-source/blob/71733ed81f4b13ac1ed1b3328cbbaa7e01afdbd2/plugins/online/filmix.js) використовує `http://filmixapp.cyou/api/v2/`, `search?story=…`, `post/{id}`, `user_profile` і `user_dev_*`; [go-filmix Discover](https://github.com/n0madic/go-filmix/blob/32e4e4f522537943a035ddf1be303782e0b7f6d0/client/discover.go) містить HTTP/HTTPS варіанти того самого host. [Побудова URL go-filmix](https://github.com/n0madic/go-filmix/blob/32e4e4f522537943a035ddf1be303782e0b7f6d0/internal/httpx/url.go) додає `user_dev_id`, `user_dev_name`, `user_dev_vendor`, `user_dev_os`, `user_dev_apk`, а за наявності — `user_dev_token`. У плагіні ці поля присутні; додатково є `app_lang=ru_RU`, APK `2.2.13`, ім'я/vendor `Lampa`, OS `Android`. Точну чинну вимогу сервера до їхніх значень без живої відповіді встановити неможливо. Це сторонні клієнти, а не офіційна специфікація чи доказ доступності API.

За [документацією XMLHttpRequest](https://developer.mozilla.org/en-US/docs/Web/API/XMLHttpRequest/status), мережеві помилки можуть давати status 0. JS не отримує достатньо деталей, щоб розрізнити DNS, TLS, CORS і розрив мережі; для [CORS-помилок](https://developer.mozilla.org/en-US/docs/Web/HTTP/Guides/CORS) потрібні деталі консолі браузера. Тому лог `http=0 error=error` не встановлює причину. Виявлений TLS-збій — доказ для цього середовища, а не остаточний діагноз TCL.

У браузері та Android WebView поточний `$.ajax` використовує XHR і підпорядковується CORS. На Android результат додатково залежить від версії WebView, DNS/мережі пристрою, довірених сертифікатів і [network security configuration застосунку](https://developer.android.com/privacy-and-security/security-config). Дозвіл змішаного HTTP/HTTPS визначає [WebSettings](https://developer.android.com/reference/android/webkit/WebSettings#MIXED_CONTENT_NEVER_ALLOW). HTTP-адреса в чужому клієнті не доводить її придатність для цього HTTPS-плагіна. Нативний Android HTTP bridge має іншу мережеву поведінку, але тут він не використовується; транспорт не замінено.

Працездатність поточного HTTPS API **не підтверджено**. Адреса залишається змінюваною. Ім'я з сертифіката не використовується як новий API; `filmix.gg` є сайтом і не замінює API. TLS не вимикали, автоматичний HTTP fallback, випадкові дзеркала й публічні проксі не додавали. Для наступного живого тесту потрібна підтверджена адреса Filmix API v2 з чинним сертифікатом і CORS або власний довірений HTTPS-проксі.

2. Відкрий «Налаштування → Lampa Online». Очікуй чотири текстові поля без TypeError й збереження попередніх значень. Вийди та відкрий налаштування знову, потім повністю перезапусти Lampa й перевір збереження всіх чотирьох полів. Back із серій веде до сезонів/озвучень, наступний — до результатів, ще один — до попереднього екрана Lampa. Для фільму: джерела → результати → попередній екран. Повтори мишею/сенсором, якщо вони доступні.
7. Запусти пошук і одразу вийди Back. Повтори з post-запитом. Пізня відповідь не повинна повернути закритий екран, змінити чужий фокус або залишити нескінченний loader. Знову відкрий компонент.
8. Вимкни мережу або тимчасово введи недоступну API-адресу. Очікуй повідомлення про помилку/таймаут і рядок повтору, без JavaScript crash і нескінченного loader. Перевір пару `start`/`complete` для `search`; із власним токеном — спочатку `user_profile`, потім `search`. За помилки профілю очікуй повідомлення та гостьовий ліміт. Для `http=0 error=error` запиши окрему причину з консолі WebView (TLS/DNS/CORS), якщо вона доступна: сам status 0 її не визначає. Пошук без результатів має завершувати loader. Для успішного пошуку очікуй `json=true filmix=true`; це ще не PASS відтворення.

Переконайся, що власні логи `LampaOnline` не містять токена, device ID, URL із query або приватних даних профілю. Після виходу Back під час запиту має бути одне завершення `error=abort`, без пізнього оновлення екрана. **Залишкові обмеження**

- Поточний API host має проблему TLS у середовищі перевірки; успішний живий сценарій ще не підтверджено. Плагін не визначає нові host-и автоматично.
- AJAX працює за правилами CORS WebView/браузера. Нативний Android HTTP bridge не використовується через його логування credential-bearing URL у перевіреному Lampa.Reguest.
- Підтримуються тільки надані джерелом прямі MP4/HLS URL та початкові шаблони якості. DASH, декодування прихованих посилань, DRM, обхід авторизації й обмежень не реалізовані.
- Реальну доступність потоку, кодеки, серверні права, геообмеження й поведінку зовнішнього Android-плеєра потрібно перевіряти вручну. Стандартний error callback покриває фатальні помилки вбудованого плеєра; зовнішній застосунок може не повідомити Lampa про помилку.
- Контракти старих/модифікованих збірок Lampa можуть відрізнятися. Критерії NOT VERIFIED не означають PASS.
