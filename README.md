# Lampa Online 0.1.1

Автономний ES5 JavaScript-плагін для пошуку фільмів і серіалів у Filmix та передавання доступних MP4/HLS-потоків у стандартний Lampa.Player. Версія **0.1.1** підготовлена до першого ручного тестування. Android, Android TV, Smart TV і браузерна Lampa: **NOT VERIFIED на реальних пристроях**.

Підтримуване джерело цього випуску — лише **Filmix API v2**. Інші джерела з ToDo.md не реалізовані. Збірка, npm і додаткові бібліотеки для встановлення не потрібні; використовується jQuery, який уже надає Lampa.

**Встановлення через URL**

1. Розмісти `lampa-online.js` на своєму статичному HTTPS-хостингу з чинним сертифікатом. URL повинен віддавати сам JavaScript, а не HTML-сторінку перегляду файла.
2. У Lampa відкрий «Налаштування → Розширення / Плагіни → Додати плагін» і введи прямий HTTPS URL цього файла.
3. Повністю перезапусти Lampa. Після оновлення з 0.1.0 також потрібен перезапуск: одночасне завантаження двох різних версій не підтримується.
4. Відкрий «Налаштування → Lampa Online» та вкажи доступну базову адресу Filmix API v2.
5. Відкрий контекстне меню картки → «Плагіни / Розширення» → «Lampa Online». Назви пунктів залежать від мови й версії Lampa.

Плагін у межах цієї роботи **не опублікований**: готової адреси встановлення немає. Git commit, push і pull request не виконувалися. Робоча папка не містила `.git`.

**Налаштування**

| Ключ Lampa.Storage | Типове значення | Призначення |
| --- | --- | --- |
| `lampa_online_api_url` | `https://filmixapp.cyou/api/v2/` | Базова адреса API, без query/hash, з `/api/v2/`. Це початкове, **не підтверджене як працездатне** значення. |
| `lampa_online_token` | порожньо | Власний Filmix device token. Пароль не потрібен. |
| `lampa_online_proxy` | порожньо | Необов'язковий власний довірений HTTPS CORS-проксі. Публічного проксі за замовчуванням немає. |
| `lampa_online_device_id` | автоматично збережені 16 hex-символів | Сталий ID пристрою. Наявне значення з 0.1.0 зберігається. Для раніше прив'язаного токена використовуй відповідний device ID. |

Параметри зберігаються стандартним Lampa.Storage; фактичне збереження на Android треба перевірити після перезапуску. Не змінюй device ID без потреби.

Проксі підтримує початковий формат **префікс + повний URL**: налаштування `https://proxy.example/` дає запит виду `https://proxy.example/https://api.example/api/v2/search?...`. Це приклади адрес, не готові сервіси. Проксі формату `?url=` чи з кодуванням усього upstream URL не підтримується. Проксі отримує токен; для upstream також слід використовувати HTTPS. Прямий HTTP API відхиляється зі зрозумілим повідомленням. Автоматичного переходу з HTTPS на HTTP немає.

**Знайдені проблеми та виправлення**

- Захист від повторного запуску був прив'язаний до версії, а завантаження до появи Lampa просто пропускалося. Тепер один сталий прапорець захищає bootstrap, очікування Lampa та реєстрації; app/ready handler видаляється після запуску.
- `Reguest.clear()` у перевіреному Lampa лише очищає callbacks, а обробник помилок логує повний URL разом із query. Мережевий транспорт локально замінено на jQuery AJAX із `global: false`, скасуванням XHR, захистом від пізніх відповідей та власним watchdog. Це цільова заміна мережевого шару, решта компонентної архітектури збережена. Пошук/post: 15 с; профіль: 8 с.
- Раніше профіль завантажувався паралельно й міг змінити обмеження якості після побудови списків. Тепер він завершується перед пошуком; рядковий прапорець `"0"` не дає PRO-доступ. За непідтвердженого профілю діє гостьовий ліміт.
- Гостьовий ліміт для шаблонів якості встановлено консервативно у 480p; підтверджений звичайний профіль — 720p, PRO — 1080p, PRO+ — 2160p. Це клієнтська політика, а не підтвердження доступу: остаточні права визначає сервер. Для прямого потоку без оголошеної роздільності, зокрема HLS master, використовується наданий URL без вигадування варіантів якості.
- Back із джерел повторно запускав пошук, міг залишати активний post-запит і втрачав вибраний результат. Тепер Back скасовує запит і відновлює кешований список та позицію фокуса. Повернення між сезонами й серіями також зберігає фокус.
- Фокус міг оновлюватися під час відкритого меню/плеєра. Тепер колекція оновлюється лише коли екран володіє активним content controller. Рядок «Назад» доступний навіть під час завантаження або порожнього результату.
- Додано перевірку JSON/структури пошуку, відкидання некоректних результатів, title/name/original_title/original_name, показ року та оригінальної назви. Порожня відповідь один раз повторює пошук за оригінальною назвою; користувач завжди сам обирає результат.
- Залишено тільки оголошені якості; `%s` без списку qualities не розгортається. MP4 і HLS передаються у стандартний Player; HTML/embed, некоректні URL та відомі якості понад ліміт відхиляються. Для серіалів підтримуються numeric episode objects, масиви та названі записи з `sNeN` у URL; номери сортуються чисельно. Сезон `-1` показується як 1.
- Прибрано циклічне посилання `first.playlist`: об'єкт запуску серіалу копіюється окремо від його playlist. Список є в даних запуску для Android bridge і передається через `Lampa.Player.playlist()` для вбудованого плеєра. Додано повідомлення при синхронному збої запуску й стандартний `error` callback для фатальної помилки потоку.
- `Storage.get()` може перетворювати цифрові token/device ID на числа, гублячи початкові нулі або точність. У цьому випадку текст читається через перевірений `Storage.value()`.
- `destroy()` тепер скасовує обидва запити й таймери, прибирає власні обробники рядків, очищує дані та замикання свого controller. Повторне знищення безпечне; чужий controller не змінюється. CSS-класи отримали префікс `lampa-online-`.

Діагностичні повідомлення плагіна мають префікс `LampaOnline` та містять лише етап, кількість або числовий статус. Текст сервера, URL, токен і дані профілю не виводяться. Сам стандартний Player Lampa може логувати переданий URL потоку; його глобальне логування плагін не змінює.

**Перший ручний тест на Android**

1. Запиши версії Lampa, Android, модель пристрою та версію плагіна (в логах має бути `LampaOnline v0.1.1.ready`). Встанови файл через прямий HTTPS URL за інструкцією вище й перезапусти застосунок.
2. Налаштуй доступний Filmix API v2. Спочатку залиш token/proxy порожніми. Перевір, що налаштування Lampa Online й пункт контекстного меню є в одному екземплярі.
3. Відкрий картку відомого доступного фільму → контекстне меню → «Плагіни / Розширення» → «Lampa Online». Очікуй окремі результати з назвою, роком та ID. Нічого не повинно стартувати автоматично.
4. Обери правильний результат, потім озвучення. Перевір відкриття стандартного плеєра, доступні якості та повернення Back на той самий рядок.
5. Перевір серіал: сезон → озвучення → список серій. Переконайся, що 2 розташована перед 10, обрана серія правильна, наступна серія є в плейлисті. Після плеєра фокус має залишитись на обраній серії.
6. Перевір Up/Down/OK. Left має переходити за правилами Navigator або відкривати меню; Right передається Navigator. Back із серій веде до сезонів/озвучень, наступний — до результатів, ще один — до попереднього екрана Lampa. Для фільму: джерела → результати → попередній екран. Повтори мишею/сенсором, якщо вони доступні.
7. Запусти пошук і одразу вийди Back. Повтори з post-запитом. Пізня відповідь не повинна повернути закритий екран, змінити чужий фокус або залишити нескінченний loader. Знову відкрий компонент.
8. Вимкни мережу або тимчасово введи недоступну API-адресу. Очікуй повідомлення про помилку/таймаут і рядок повтору. Поверни мережу/правильну адресу та повтори запит. Перевір пошук без результатів. Для відтворюваних 401/403/404/429/5xx потрібен власний тестовий API/проксі.
9. За потреби введи свій легітимний token і відповідний device ID. Повторно відкрий компонент: обмеження якості має відповідати підтвердженому профілю та оголошеним джерелом варіантам. Реєстрація акаунта або отримання токена плагіном не виконується.
10. Повністю закрий і запусти Lampa. Перевір збереження параметрів, повторне відкриття фільму/серіалу та відсутність дублікатів. Зафіксуй кожен результат як PASS/FAIL із кроками відтворення; до цього статус пристрою залишається NOT VERIFIED.

**Залишкові обмеження**

- Поточний API host має проблему TLS у середовищі перевірки; успішний живий сценарій ще не підтверджено. Плагін не визначає нові host-и автоматично.
- AJAX працює за правилами CORS WebView/браузера. Нативний Android HTTP bridge не використовується через його логування credential-bearing URL у перевіреному Lampa.Reguest.
- Підтримуються тільки надані джерелом прямі MP4/HLS URL та початкові шаблони якості. DASH, декодування прихованих посилань, DRM, обхід авторизації й обмежень не реалізовані.
- Реальну доступність потоку, кодеки, серверні права, геообмеження й поведінку зовнішнього Android-плеєра потрібно перевіряти вручну. Стандартний error callback покриває фатальні помилки вбудованого плеєра; зовнішній застосунок може не повідомити Lampa про помилку.
- Контракти старих/модифікованих збірок Lampa можуть відрізнятися. Критерії NOT VERIFIED не означають PASS.
