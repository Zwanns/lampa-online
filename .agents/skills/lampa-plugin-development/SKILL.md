# Lampa Plugin Development

Використовуй для створення, модифікації, тестування й налагодження JavaScript-плагінів Lampa. Застосовуй правила та тематичний індекс із кореневого [AGENTS.md](../../../AGENTS.md); не завантажуй усі довідники без потреби. Скіл описує процес, а обсяг змін визначає поточне завдання користувача.

## Робочий процес

1. **Визнач вимоги.** Зафіксуй потрібну поведінку, критерії приймання та заборонені зміни. Прочитай повністю `ToDo.md`, лише якщо завдання посилається на нього. Перевір `git status`, відповідний JS і тести; відділи власні зміни від уже наявних. Для діагностики визнач відтворюваний збій, stage і середовище.
2. **Знайди документацію.** Обери документи через індекс AGENTS: lifecycle/events для реєстрацій, navigation/controller для TV UI, settings/storage для конфігурації, player для playback, окремий звіт для Filmix/Rezka. Читай відповідні розділи й потрібні первинні джерела; навчальні приклади та старі мережеві результати не вважай поточною специфікацією.
3. **Перевір API.** Для потрібних методів/подій зістав експорт, сигнатуру, payload і cleanup із вихідним кодом конкретної версії Lampa або доступним runtime. Запиши джерело/версію та що лишилося припущенням. Не покладайся лише на mock або номер версії. Якщо інформації немає, явно вкажи це й обмеж реалізацію підтвердженим контрактом; експериментальну інтеграцію роби лише коли це допускає завдання.
4. **Спроєктуй вузьку зміну.** Визнач точку входу, стан екрана, transport і завершення запитів, Back/фокус та cleanup. Зберігай наявні адаптери й технічні ідентифікатори; новий провайдер ізолюй. Не змінюй глобальні методи Lampa або Player. Для мережевої проблеми відділи DNS/TLS/HTTP від parsing/schema та playback; обери наступну перевірку за доказами.
5. **Реалізуй.** Дотримуйся standalone ES5 і правил AGENTS. Забезпеч однократний bootstrap, scoped handlers, timeout/cancellation, захист від stale callbacks та безпечний текст у UI. Не копіюй сторонні модулі/секрети, не вигадуй якості й потоки. Діагностика має містити лише дозволені metadata; challenge/авторизація зупиняють сценарій без обходу.
6. **Перевір.** Для змін JS виконай команди з AGENTS: syntax, offline suite з ES5 check і diff check. Додай потрібні synthetic regression-fixtures/тести, зокрема для помилки, retry, Back, destroy і повторного відкриття. Мережеві проби роби лише коли вони потрібні завданню, із нормальним TLS та синтетичними даними. Для документаційних змін перевір структуру/посилання, для SKILL — YAML frontmatter; не запускай несумісні npm scripts із прикладів документації.
7. **Підготуй встановлення й ручну перевірку.** Для нового/зміненого плагіна поясни, який JS віддавати за прямим HTTPS URL, як додати/оновити розширення та повністю перезапустити Lampa. Зазнач потрібні settings і короткі сценарії фільму/серіалу, D-pad/OK/Back, повторного відкриття й Player. Використовуй наявні інструкції в `docs/README.md` та provider-звіті; оновлюй їх лише якщо це входить в обсяг. Не публікуй файл автоматично.
8. **Звітуй українською.** Вкажи результат, змінені файли, фактичні перевірки й кількість тестів, спосіб встановлення/перевірки та залишкові ризики. Розділи LOCAL PASS, NETWORK VERIFIED і TCL VERIFIED; невиконане познач NOT VERIFIED. При збоях назви підтверджений етап і наступний обґрунтований крок, не оголошуй API чи playback виправленими за mocks або HTTP 200. Перевір фінальний diff і дотримання обсягу; commit/push потребують прямої вказівки користувача.
